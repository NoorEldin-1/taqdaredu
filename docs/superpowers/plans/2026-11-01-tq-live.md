# TQ-LIVE Implementation Plan — live one-to-one and group sessions

> **For agentic workers:** executed by parallel subagents, one task each, each in its own git
> worktree branched from `feature/tq-live`. The controller session reviews, merges, runs the
> browser checks, pushes and deploys. Implementers NEVER push, deploy, open a browser, or
> dispatch subagents. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Deliver the whole of `docs/plans/live-classroom-plan.md` (the spec): improved one-to-one
live sessions (join windows, derived states, countdowns, calendar, server-side join, instant
booking), rescheduling and reasoned cancellation, attendance and recordings, and group live
sessions as the sixth sale unit.

**Architecture:** No second engine. One-to-one sessions stay on `Taqdar_sessions_model`
(tables `tutoring_sessions` / `availability_slots` / `tq_teacher_windows`). Groups are a new
`Taqdar_group_model` whose purchase is a `subscriptions` row (`group_id`) with its invoice,
settled by Tap / bank exactly like course and book sales. The room is an **external link**
(Zoom / Meet) — no embedded room.

**Tech Stack:** CodeIgniter 3, PHP 8.2, MariaDB, server-rendered PHP views, vanilla JS
(`assets/taqdar/js/taqdar.js`), no build step.

**Spec:** `docs/plans/live-classroom-plan.md` — decisions D1–D10 in section ٠ are binding.
Read the sections your task names; do not read the whole file unless told.

## Global Constraints

- Read `CLAUDE.md` sections: «الحصص الخاصة» (TQ-SESSION-PAY, TQ-SESSION-GRID), «TQ-FOUNDATION»,
  «TQ-FND-PACK», «TQ-COURSE-SALE», «TQ-BOOK», «TQ-SOLD-NAME», «TQ-COUPON», «واجهة البرمجة».
- Line endings: the repo is mixed CRLF/LF **file by file**. Before committing, count with PHP
  (`php -r '$s=file_get_contents($f);echo substr_count($s,"\r\n")," ",substr_count($s,"\n");'`)
  and keep each modified file in its original style. New files: LF. Never bulk-convert.
- `php -l` every modified PHP file. Never edit `system/` or `application/libraries/`.
- UI text Arabic, **no tashkeel** (U+064B–U+0652). Write new UI strings as plain Arabic; i18n
  wrapping happens in Task 6 — do not hand-edit `application/language/tq/english/*`.
- Schema is created at runtime: `install_schema()` / `ensure_schema()` with a version setting,
  `ADD COLUMN IF NOT EXISTS`, and called **before every read** of new columns. Every admin read
  of new tables wrapped in `safe_rows` / `safe_scalar` style try/catch **with `reset_query()`
  in every catch** (TQ-BUILDER-DIRTY).
- Production DB is UTC: compare times in PHP (`time()`, `date()` with explicit values), never
  `NOW()`/`CURDATE()` for new logic. Display: Riyadh in server text, browser `Intl` in JS.
- Write routes go **before** view routes in `routes.php`. Write handlers use `write_guard()`
  and ownership guards. Every new form prints `tq_csrf()`.
- Money in halalas internally; `course.price`-style SAR columns converted in one place.
- Every new feature switch defaults so that **nothing changes** when off, except D1
  `tq_session_instant_book` which defaults ON (pending `requested` rows still finish on the old path).
- Notifications only through `Taqdar_admin_model::push_notification()`. WhatsApp only for money.
- Tests: offline PHP scripts in `tests/` following `tests/mobile_config_test.php` (stub
  `BASEPATH`, `CI_Model`, `get_settings`, `t`; instantiate via reflection; `check()`; print
  `OK n checks`). Test pure logic (state derivation, windows, ics, splits, capacity math).
  Run: `php tests/<file>.php`.
- Commit messages English only, one commit per logical slice, ending with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Do not stage untracked files you did not create (repo root has many stray `.txt/.md/.pdf`).
